# 小伙伴 · 复习刷题台

一个完全跑在本地、由你自己的大模型 Key 驱动的刷题工具。把复习资料丢进去，它自动整理成题库，然后按选择题的方式刷——可自动判分、统计正确率、记录掌握情况。

没有后端、没有账号、不联网存档。所有题库和学习记录都保存在你自己的浏览器里。

---

## 为什么做这个

把资料交给 AI 出题，然后复制到 iPad 上做——做完只有"对了几道"，没有积累感。

这个工具想解决的是另一件事：**让刷题有迹可循**。你今天学了多久、做了多少题、哪些知识点反复错、离考试还剩多少进度，都能看见。

---

## 核心功能

### 1. 资料 → 题库（大模型在应用内生成）

支持拖入 `txt` / `md` / `json` / `pdf` / `docx`，由大模型整理成结构化题库。

**两种模式，粘贴后自动判断，也可以一键切换：**

| 你上传的东西 | 平台怎么做 |
| --- | --- |
| 已经是一套题（试卷、练习册、ima 生成的题库） | **只整理，不出题**：原文有几道就整理几道，题干和选项原样保留，不新增、不改写、不合并。「每章题量」会自动隐藏 |
| 知识点整理、讲义、笔记 | 按章节把知识点变成选择题，每章出 N 道（N 可选 3/5/8/10，默认 5） |

- 现成题目若原文没给答案，模型会自己判断并标注「答案由模型补」，预览页汇总提示，方便你核对
- 多选题（答案如 `ABD`）会识别成多选，刷题时可以选中多项
- 简答 / 论述 / 计算题照原样保留，同时改写成一道四选一选择题（标记「开放题改写」）
- 每道题打上知识点标签，用于掌握度统计

长资料**按章节分批出题**：识别「第X章 / 第X节 / 一、二、 / ## 标题」这类结构，每 3 章一批、每批单独请求。现成题目则按题号分批（每批 10 道）。合并时按题干去重，同一道题不会重复收录。

> 各种格式的实测效果、以及「一题一块」的推荐写法，见下面的 [上传什么资料最合适](#上传什么资料最合适)。

> 题不是我来出的，是你自己的 Key 出的。平台只提供协议和界面。

### 2. 刷题

- 单题一屏，选完即时反馈（对错 + 解析 + 知识点）
- 支持按题库、按知识点、按错题本进入
- 错题自动归档，答对可移出

### 3. 学习仪表盘

| 指标 | 说明 |
| --- | --- |
| 有效学习时长 | 只算真正在看的时间：切到别的标签页、或 60 秒无操作自动暂停 |
| 累计题量 / 今日题量 | 按题库、按天统计 |
| 正确率 | 今日与累计分开看 |
| 掌握知识点 | 依据标签下的答题表现推算 |
| 目标进度 | 设定考试日期与目标题量，显示还差多少 |
| 累计天数 | 有学习记录的天数 |

风格上刻意克制：没有等级、没有金币、没有排行榜。目标是"看见自己在前进"，不是"再刷五道解锁奖励"。

成就分两组：**每日纪录**（单日 20 / 50 / 100 / 200 题、单日 60 / 120 分钟、单日正确率 90%）和**长期成就**（连续天数、累计题量）。每日徽章按历史最佳单日判定，一次达成就永久点亮，未解锁的卡片上直接显示"今天 12 / 20 题"。**一天二十道就值得夸**——门槛刻意压得低。

### 4. 鼓励与名言

- 每 10 题触发一次轻量鼓励（120+ 句库，非模态，不打断作答）
- 每天一句中英双语寄语（110 条，中外古今，不只谈学习；不考据出处，只当氛围）

### 5. 题库分文件夹

按学科建文件夹，题库归到对应文件夹下，列表可折叠。期末周同时复习几门课的时候不至于乱。

## 上传什么资料最合适

这一节是给「题目已经有了、只差刷题体验」的人写的。如果你的题是在 **ima 知识库**里生成的，按下面做最省事。

> 已经是一整套题（试卷、练习册、ima 生成的题库）时，平台会自动进入**「整理原题」**模式：只把你原有的题结构化，**不会**再多生成题。「每章题量」这类出题参数会自动隐掉，如果你其实想让模型出题，点说明条右侧的「改让模型出题」就行。

### 最省事的流程

1. 在 ima 里生成题目，让它按「题干 / 选项 / 答案 / 解析」的结构输出（提示词见本节末尾）
2. 把结果导出成 **Markdown（`.md`）**，或直接全选复制、粘进导入框
3. 拖进「导入」，点「整理成题库」

### 格式怎么选

| 格式 | 推荐度 | 实际表现 |
| --- | --- | --- |
| `.md` | ★★★★★ | **最合适**。ima 的笔记和问答导出就是 Markdown，标题、列表、LaTeX 公式原样保留 |
| `.txt` | ★★★★☆ | 一样好用。纯文字即可，公式写成 LaTeX 原文（如 `$x^2$`）能正常识别 |
| `.json` | ★★★☆☆ | 按纯文本读入。里层是题目文字就没问题；嵌套很深的原始数据会白烧 token |
| `.docx` | ★★★☆☆ | 能用（走 Word 文字提取），但表格和公式容易走样，导完扫一眼 |
| `.doc` | ✗ | 老的二进制格式读不出来，请先「另存为 `.docx`」 |
| `.pdf` | ★★☆☆☆ | **只支持文字型 PDF**。扫描件、拍照转的 PDF、图片拼的讲义读不出字，会提示「没有读到文字」 |

### 内容上什么样最好用

一句话：**一题一块，题干、选项、答案、解析齐全。**

```md
## 第 3 章 导数应用

### 1. 单选
题干：函数 f(x)=x³-3x 的极小值点是？
A. x=-1
B. x=1
C. x=0
D. x=±1
答案：B
解析：f'(x)=3x²-3，令其为 0 得 x=±1；f''(1)=6>0，故 x=1 为极小值点。
知识点：极值判定

### 2. 计算（保留原题，平台会改写成选择题）
题干：求 f(x)=x³-3x 在区间 [-2,2] 上的最大值与最小值。
答案：最大值 2，最小值 -2
解析：比较端点与驻点的函数值即可。
知识点：闭区间最值
```

几个要点：

- **已经是选择题的，原样给就行**，不用改，准确率最高
- **计算题、简答题、证明题直接给原题和答案**。改写成四选一是平台干的事——自己先改一遍容易丢信息、丢条件
- **答案和解析跟着题走**，别按「题目全在前面、答案统一在文末」排。平台能尽力对齐，但拆开写容易错位
- **每题尽量带知识点标签**。不写的话会让模型自己推断，掌握度统计会粗一些

### 一次导多少

- **一份一个学科/一本书**最合适。有章节结构时会自动按章分批，不用你手动切
- 每批最多 3 章 / 6000 字，最多 12 批（约 36 章）。超出会在摘要里提示哪些没处理
- 批数越多越慢：5 章大约 2 次请求、十几秒；20 章大约 7 次请求、一两分钟
- 题量由「每章题量」控制。知识点密集的科目（如法条、定义多的）建议选 8 或 10
- 别一次把整学期 PPT 全丢进来，宁可拆成几份

### 什么资料效果差

- 纯讲义、没有题目 → 模型只能凭空出题，容易空泛、超纲
- 只有答案没有题干 → 对不上号
- 截图、扫描件、手写照片 → 读不出文字，请先 OCR 成文本
- 一页几十道题的密集表格 → 转换后题号容易粘连，建议先整理成「一段一题」

### 给 ima 的提示词

在 ima 里让它按这个结构输出，导出来就能直接用：

> 请把上面的内容整理成题库，用 Markdown 输出。每题包含：题干、选项、答案、解析、知识点。已有的选择题保留原选项（四个选项）；计算题和简答题**保留原题与完整答案，不要改写成选择题**。题目之间空一行，题号连续。

## 快速开始

### 方式一：桌面版（推荐，无跨域限制）

```bash
git clone <本仓库地址>
cd xiaohuoban
python launcher.pyw          # 或者双击 launcher.pyw（无窗口）
```

会自动在 `8778–8827` 里挑一个空闲端口起本地服务，并用 Edge/Chrome 的 `--app` 模式打开独立窗口。图标、数据、日志都在当前目录，不往 C 盘写东西。

需要 Python 3.8+，无第三方依赖。

### 方式二：直接开网页

用任意静态服务器指向 `app/` 目录即可：

```bash
cd app && python -m http.server 8080
```

然后在浏览器打开 `http://127.0.0.1:8080`。

## 配置大模型（BYOK）

打开「设置」→ 选服务商 → 填 API Key。Key 只存在本地浏览器里，不会发往除模型厂商之外的任何地方。

| 服务商 | 网页版可用 | 说明 |
| --- | --- | --- |
| **OpenRouter** | ✅ | 默认推荐。一个 Key 覆盖主流模型，有免费模型，且开放浏览器跨域 |
| 智谱 GLM | ⚠️ | 浏览器直连会被跨域拦截，**桌面版可用** |
| DeepSeek | ⚠️ | 同上 |
| 通义千问 | ⚠️ | 同上 |
| Kimi | ⚠️ | 同上 |
| 自定义 | — | 任何 OpenAI Chat Completions 兼容端点 |

> **为什么会跨域报错？** 浏览器直连第三方 API 时，服务商必须显式允许网页来源（`Access-Control-Allow-Origin`）。国内多数厂商没有开放这个头，所以网页版连不上——这不是 Key 的问题。桌面版通过 `launcher.pyw` 里的 `/api/llm` 端点做本地转发，绕开了浏览器限制，所以任何厂商都能用。

## 数据存在哪

- **题库、答题记录、设置** → 浏览器 IndexedDB（桌面版落在 `./_profile/`）
- **API Key** → 同一份本地存储，不加密，不上传

换电脑或者重装，数据就没了。重要的题库建议在「题库」里导出 JSON 备份。

## 目录结构

```
xiaohuoban/
├── launcher.pyw          # 桌面启动器：本地服务 + LLM 转发 + 独立窗口
├── icon-cat.ico          # 看书的橘猫
└── app/
    ├── index.html
    ├── styles.css
    ├── js/
    │   ├── app.js               # 视图路由与渲染
    │   ├── llm.js               # BYOK 协议层、提示词、长文分段
    │   ├── db.js                # IndexedDB 封装
    │   ├── achievements.js      # 统计与鼓励逻辑
    │   ├── data-encouragements.js
    │   └── data-quotes.js
```

PDF 解析用 pdf.js，DOCX 解析用 mammoth.js，两个库都已放进 `assets/`，断网也能用。

## 已知限制

- 单次导入有分段上限（20 段 × 8000 字符），超长资料会被截断并在摘要里提示
- 大模型改写出的选择题偶尔会有语义偏差，涉及原则性问题建议回原资料核对
- 数据仅本机，没有同步，没有多端
